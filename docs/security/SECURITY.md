# Security design

See `SECURITY_REPORT.md` for the latest suite run (generated by `python scripts/run_security_suite.py`).

| # | Required scenario | Test | Defense |
|---|---|---|---|
| 1 | HR employee → IT confidential | `test_01…` | ACL clause in the retrieval SQL |
| 2 | IT employee → HR salary | `test_02…` | same |
| 3 | Restricted metadata | `test_03…` | 404 identical to nonexistent |
| 4 | Archived/draft/deleted | `test_04…` | status in ACL clause + ACTIVE version join; chunks purged on delete |
| 5 | Department parameter | `test_05…` | parameter can only narrow (AND) |
| 6 | Document id enumeration | `test_06…` | per-id ACL, uniform 404 |
| 7 | Prompt injection (question and document) | `test_07…`, `test_07b…` | LLM never sees unauthorized text; sources delimited and sanitized; citation validation |
| 8 | MCP/agent bypass | `test_08…` + `test_mcp.py` | strict tool args (`extra=forbid`), server-side identity |
| 9 | Another user's conversation | `test_09…` | owner-only sessions, uniform 404, audited |
| 10 | Version history | `test_10…` | only the ACTIVE version is indexed/served; versions endpoint returns metadata only |

Additional: JWT tampering/`alg=none`/expiry/revocation, inactive users, forged identity headers ignored, audit logs free of secrets,
unauthorized markers absent from results, reranker candidates, LLM prompts, citations and MCP outputs for every role.

## Known limitations
- No login rate limiting / account lockout, no TLS termination, no secret manager (use a reverse proxy and a vault in production).
- Token stored in `sessionStorage` (XSS-exposed by design; httpOnly cookies + CSRF protection would be stronger).
- Tests use a scripted LLM: they prove the LLM *cannot* receive unauthorized text, not that a real LLM resists jailbreaks.
- Prompt-injection regexes only produce audit signals; they are not a defense.
- Not penetration-tested. Not verified on PostgreSQL/pgvector in the build environment.
